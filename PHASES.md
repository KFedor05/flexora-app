## ⚪ Фаза 1. Каркас Tauri

**Цель:** запустить пустое Tauri-приложение с системным треем, single-instance, сохранением состояния окна.

**Задачи:**
- [ ] Установить Rust toolchain в WSL
- [ ] `npm create tauri-app@latest` с шаблоном `vanilla`
- [ ] Настроить структуру проекта (`src/` frontend, `src-tauri/` backend)
- [ ] Подключить Vite + Tailwind CSS + Inter + Lucide
- [ ] Установить плагины:
  - `tauri-plugin-store` — хранилище
  - `tauri-plugin-autostart` — автозапуск
  - `tauri-plugin-dialog` — файловые диалоги
  - `tauri-plugin-fs` — файловая система
  - `tauri-plugin-opener` — открытие URL и папок
  - `tauri-plugin-notification` — системные уведомления (v1.1+)
  - `tauri-plugin-window-state` — сохранение размера/позиции окна
  - `tauri-plugin-single-instance` — единственный экземпляр
  - `tauri-plugin-os` — определение системной темы
- [ ] Базовый main процесс + окно (минимальный размер 900×600, можно сжимать до 600 для проверки collapse)
- [ ] Single-instance: повторный запуск exe фокусирует существующее окно вместо создания нового
- [ ] Window state: размер и положение окна сохраняются между запусками
- [ ] Системный трей с минимальным меню (Открыть / Выйти)
- [ ] Сворачивание в трей при закрытии окна (вместо exit)
- [ ] Базовый layout (левый sidebar + main + правая панель)
- [ ] Тёмная тема как стартовая
- [ ] Подключить i18next, базовые `en.json` и `ru.json`

**Done = `cargo tauri dev` запускает пустое окно с трей-иконкой, минимальным layout-ом, английским по умолчанию. Повторный запуск фокусирует окно. Размер окна запоминается.**

## ⚪ Фаза 2. Хранилище и схема данных

**Цель:** заложить базу данных, безопасное сохранение, контракт API между Rust и JS.

**Задачи:**
- [ ] Определить Rust-структуры (`Habit`, `Counter`, `Section`, `Day`, `Streak`, `Settings`)
- [ ] Сериализация через `serde_json`
- [ ] **Atomic write**: запись через временный файл + переименование (защита от битых файлов при сбое)
- [ ] Загрузка с восстановлением (если основной файл битый — попытаться загрузить backup)
- [ ] Backup last good copy при каждой успешной записи
- [ ] Tauri commands: CRUD для habits, counters, sections, days, settings
- [ ] Базовая валидация (имя не пустое, цель счётчика > 0, имя ≤ 60 символов)
- [ ] Валидация на стороне Rust (frontend не доверять, всё проверять)
- [ ] JS-обёртка для вызова Rust-команд (clean async API)
- [ ] Обработка ошибок Tauri commands (Result<T, String>)
- [ ] Логирование ошибок в файл `~/.config/flexora/app.log` (для отладки)

**Done = из JS-консоли можно создать привычку, прочитать её, удалить — данные сохраняются между запусками. При выключении компа в момент записи — данные не теряются.**

# Как работаем

1. Я начинаю Фазу N автономно
2. В процессе показываю промежуточные результаты, спрашиваю что-то критичное
3. В конце фазы пишу "Фаза N завершена — что сделал, как проверить"
4. Ты проверяешь, тестируешь, даёшь фидбек
5. Если ОК → отмашка "переходи к Фазе N+1"
6. Если нет → правки в рамках текущей фазы

**Жду твоего "ОК Фаза 1" чтобы стартовать.**
